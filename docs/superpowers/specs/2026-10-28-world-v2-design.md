# Agent Town 世界 v2 设计

日期：2026-10-28 · 状态：待负责人批准 · 前置：`docs/decisions.md` D1–D13

## 1. 为什么做这一版

v1 世界已经能跑（两个阵营、按项目分镇、5 级成长、桥、LOD、M4 60 fps），但负责人看了觉得「设计上还是差点意思」。我对当前截图的诊断：

1. **每个镇是同一个模子**：一圈一模一样的小房子 + 同样 9 座建筑 + 中间工地。13 个镇像同一个印章盖了 13 次，项目之间看不出差别。
2. **主角太小**：镇级视角下干活的代理只有几个像素，画面大部分给了外圈静止的房子。产品的核心是「看代理工作」，现在最难看清的恰恰是它。
3. **房子不讲故事**：外圈一排排同样的盒子，只有楼高、屋顶颜色两个变量。
4. **界面像通用后台**：白色圆角卡片；右上角图例要人去解码；没有「现在正在发生什么」。
5. **不能局部放大到一个任务**：只能双击整个镇或滚轮缩放。

负责人选择这一版四块全做，并决定：**接入真实日志**（只在本机显示，不上传）；**视觉方向沿用暖陶玩具镇，往精做**。

## 2. 目标 / 非目标 / 反目标

**目标**
- G1 点击一个任务（房子 / 工地 / 小人）就能放大到它，并读到这个任务完整的经过。
- G2 每个镇的形状由这个项目真实被改动的代码长出来，不同项目一眼不同。
- G3 代理工作中的关键事件（压缩、等你、被拒绝、联网、换模型）在世界里有可读的表现。
- G4 视觉与界面升级到「看起来像一个游戏世界」，同时每个元素仍然对应真实数据。
- G5 默认读本机真实日志；模拟数据保留为 `?demo=1`。

**非目标（这一版不做）**
- 实时增量模式（计划第 4 阶段的 chokidar 监听）。这一版是「加载时读一次，可手动刷新」。
- SQLite、价格表、2D 仪表盘、声音。
- M1 Air 实测（没有这台机器）。

**反目标（即使能跑也算失败）**
- 任何元素只是装饰、不对应日志里的真实字段（违反「每个元素映射真实数据」，D11.3）。
- 编造数字：缺数据就显示「—」或不画，不估算。
- 真实日志内容离开本机：不上传、不进 git、不放进测试快照；截图只放本机。
- 真实数据下掉到明显卡顿（M4 生产构建 < 50 fps）。
- 第一次打开要等很久却没有进度提示。

## 3. 数据：接入真实日志

**现状**：`scripts/parse.ts` 已能把本机日志转成统一事件，本机实测 10 个 Claude 会话 + 476 个 Codex rollout ≈ 29.3 万事件、3,114 个任务、约 40 秒。前端目前只吃 `packages/mock`。

**设计**
- **本地服务**：新增 `scripts/serve.ts`（Node 22 直接跑 TS，`node:http`，只绑定 `127.0.0.1`）。它用现有适配器解析日志，提供：
  - `GET /api/world`：世界所需的**任务摘要**（每个任务一行：阵营、项目、会话、开始/结束时间、成功与否、标题、token 四项、模型、按角色的调用次数、触及的文件路径列表及每个文件的读/改次数、返工文件、子代理数）。房子、街区、桥、等级全从这里算。
  - `GET /api/task/:id`：这个任务的完整事件（任务日记与重放用），按需加载。
  - `GET /api/live`：最近仍在进行（未见 task_end 且最近 N 分钟有写入）的任务的完整事件——工地动画用。
  - `POST /api/refresh`：重新扫描。
- **缓存**：解析结果按源文件 mtime+size 缓存在 `~/.agent-town/cache/`（不在仓库里）。第二次启动只重解析变过的文件。
- **开发**：Vite 把 `/api` 代理到 serve.ts；生产：serve.ts 同时托管 `packages/web/dist`。一条命令 `pnpm start` 起服务并打印本机地址。
- **加载体验**：首屏显示扫描进度（已读文件数 / 总数），不是白屏。
- **模拟数据**：`?demo=1` 继续用 `packages/mock`，页面角标照旧标明「演示数据」。
- **前端改动**：store 从「一个事件数组」变成「任务摘要 + 按需加载的任务事件」。`buildLedger` 对历史只需要摘要级 token；任务卡里的分项 token 来自摘要。
- **任务标题**：Claude 用日志里的 `ai-title` / `custom-title` 记录；没有时用该任务第一条用户消息的第一行，截到 80 字。Codex 用线程名，没有时同样取第一条用户消息首行。标题只在本机页面显示。
- **项目路径**：沿用当前 `projectId`（工作目录绝对路径）。文件路径统一转为相对项目根；在项目根之外的路径归入一个「镇外」类别（不进街区，任务日记里照常显示）。

## 4. 点击放大 + 任务日记（G1）

**交互**
- 悬停：保持现在的卡片。
- **单击房子（已完成任务）**：镜头推近到这栋房子（缩放约 40），右侧滑出「任务日记」面板。
- **单击进行中的工地**：镜头锁定工地，日记实时滚动。
- **单击小人**：镜头跟随这个小人（保持等距视角，只平移跟随），头顶气泡写当前动作（「改 client.ts」「跑测试」）。
- 双击镇：照旧飞入。`Esc` 或面板上的「返回」回到上一级（任务 → 镇 → 世界）。
- 选中状态写进 URL hash（`#task=<id>`），刷新或分享本机链接能回到同一处。

**任务日记内容**（全部来自 `/api/task/:id`）
- 标题、阵营、项目、模型、开始/结束时间、用时、结果。
- token：合计与四项拆分；其中子代理占多少。
- **步骤时间线**：每一步一行——时间、角色图标、工具名、目标（文件或命令）、这一步的 token；失败/拒绝标红；子代理折叠成可展开的一组。
- 返工：哪个文件被反复改了几次（`insights.ts` 现成规则）。
- 触及的文件：按目录分组，点一个文件，镜头移到它在街区里的位置（见第 5 节）。
- **重放**：按钮在这栋房子的位置上从地基重新盖一遍（复用现有 timeline 动画，作用在这个地块上）；时间轴切到这个任务的时间段。

## 5. 代码长出来的街区（G2）

**原则**：镇的形状 = 这个项目里真实被碰过的目录和文件。我们只知道被碰过的文件（日志里的工具目标），所以街区只画这些，这正好就是「代理在这里工作过」的地图。

**布局**
- 广场在镇中心，保留任务大厅、岗亭、仓库和 9 座工具建筑围在广场边（它们表示「怎么做」）。
- **一级目录 = 从广场放射出去的主街**；子目录 = 从主街分出的小巷；**文件 = 沿街的地块**。
- 街的长度与地块数随文件数增长；街道方向由目录名哈希决定并做避让，保证同一项目每次加载布局一样，新文件出现只在街尾追加，不打乱已有地块。
- 每个镇最多画约 150 个文件地块；超出时每条街末尾放一个「其余 N 个文件」的地块。
- 根目录下的文件沿广场外圈排列。

**任务房子挪到街上**
- 每个完成的任务是一栋房子，建在**它改动最多的那条街**上（没改文件的任务建在广场外圈）。镇因此在真正干活的方向上生长，而不是一圈环形。
- 房子造型由任务的主导角色决定（以改为主 = 作坊，以读/查为主 = 塔楼，以测试为主 = 带检验台，以联网为主 = 带风向标），楼高 = token 规模（沿用 D13 公式），屋顶灰 = 失败，绿旗 = 成功。
- 每个镇最多画的房子数沿用 D13 上限，旧任务计数不画。

**地块的表现**
- 只读过的文件：低矮小花园；改过的文件：小屋，被改次数越多越精致（3 档）；触发过返工的文件：墙上有裂缝。
- 悬停地块：文件路径、读/改次数、最后一次被哪个任务碰。

**代理怎么走**
- 读/改**有文件目标**的工具调用：小人走到那个文件的地块门口干活，手里拿对应角色的道具（书 = 读，锤子 = 改）。
- 没有文件目标的工具（命令行、测试、联网、MCP 等）：照旧去对应的工具建筑。
- **路越走越宽**：每段路记录被走过的次数，宽度和颜色深浅随之变化，显示这个项目的工作习惯。

## 6. 代理的生活细节（G3）

每一条都对应已有的事件字段：

| 日志里发生的事 | 世界里的表现 |
|---|---|
| `compaction`（上下文压缩） | 小人背包装满后走到仓库卸货，背包回到压缩后的比例（现有逻辑已算背包占用，这一版加动作） |
| `awaiting_user`（等你回复/审批） | 小人站在任务大厅门口摇铃，大厅上方亮灯；你回复后熄灭 |
| `status: denied`（权限拒绝） | 岗亭栏杆落下，小人被挡回 |
| 联网工具（WebSearch/WebFetch 等） | 港口有船出海、回港 |
| `model` 字段 | 不同模型穿不同服装/帽子（Opus、Sonnet、Haiku、Codex 各模型），图例里可查 |
| 子代理派出/归来 | 现有脚手架之外，加派出时从大厅列队出发、归来时交回卷轴的动作 |
| 测试失败 / 返工 | 沿用灰烟、乌云，并在对应文件地块上冒烟 |

模型 → 外观的映射表放在配置里（类似 `roles.json`），没见过的模型用默认外观并在悬停卡里写出模型原名。

## 7. 视觉与界面（G4）

**世界**
- 镇不再是正圆盘：地面随街道外扩成不规则形状；城墙沿实际外沿走。
- 小人放大约 1.6 倍，造型更有性格（头身比、走路摆动、工作动作）；镜头默认离近一些。
- **昼夜**：天色跟随回放时刻在你本机时区的钟点（凌晨工作就是夜景、窗户亮灯）。
- **天气**：最近 30 分钟（回放时间）的失败率高时转阴/下雨，正常时晴。
- 光影：更暖的低角度主光、更清晰的轮廓与阴影；保持 60 fps 预算。

**界面**
- 统一的暖色「羊皮纸」游戏风面板，替换白色圆角卡。
- **小地图**（左下）：全世界缩略，标出当前视野和正在施工的镇，可点击跳转。
- **事件流**（右侧，可收起）：「web-shop · 指挥官派出 3 个子代理去图书馆」，点一条飞到事发地点。
- 图例改为首次进入的简短引导 + 悬停即解释，不再常驻一块难懂的方框。
- 顶部 HUD 保留数字（真实数据下照样「未配置价格」）。

## 8. 规模与性能

真实数据下要扛住：约 100 个项目、几千个任务、单镇几百个文件。
- 世界加载只用任务摘要；完整事件只在选中任务、进行中任务时加载。
- 房子、地块、路段全部实例化绘制；超上限的部分计数不画（第 5 节）。
- 验收：M4 生产构建世界视图与镇视图 ≥ 55 fps（p95 ≤ 20 ms），用真实数据测；`fps.mjs` 扩展到真实数据路径。

## 9. 测试与隐私

- **单元测试**（Vitest）：街区布局对各种输入——0 个文件、1 个文件、1000 个文件、很深的路径、同名目录、项目根外的路径、Windows 风格路径、中文文件名；布局稳定性（加一个新文件，已有地块不动）。日记数据组装、模型外观映射、昼夜/天气函数。
- **服务测试**：用 `fixtures/`（无正文、git 忽略）跑 `/api/world`、`/api/task/:id`，并与 `parse.ts` 的 token 总数对账，必须一致。
- **浏览器测试**（Playwright，演示数据）：点击房子 → 镜头到位 + 日记出现；点小人 → 跟随；Esc 返回；小地图点击；URL hash 恢复。
- **隐私**：真实日志、缓存、真实数据截图都不进 git；测试只用演示数据和无正文的 fixtures；服务只绑定 127.0.0.1。

## 11. 留给实现者决定的

- 面板、按钮的具体尺寸、动效曲线、配色微调（在暖陶玩具镇范围内）。
- 街道避让算法的具体实现，只要满足「稳定、追加不打乱」。
- 各模型的具体服装造型。
- 缓存文件格式。

## 12. 实现前已定的细节（审阅后补充）

标「负责人」的是负责人的决定，标「我的决定」的是我按现有代码和常理定的，负责人可以推翻。

1. **文件路径从哪来（负责人）**：
   - 确切来源：Claude `Read`/`Edit`/`Write`/`NotebookEdit` 的 `file_path`，Codex `apply_patch` 的 `*** Add/Update/Delete File:` 头。
   - 推断来源：简单读命令（`cat`、`sed -n`、`head`、`tail`、`rg`/`grep` 后跟的路径；Claude `Bash` 与 Codex `exec_command` 都算），**只在该路径确实是项目里存在过的文件时**计入。地块与悬停卡上标「推断」，和桥的「推断」同一套措辞。
   - `Grep`/`Glob` 的 pattern 不算文件。
   - 适配器新增一个**不截断**的 `files: { path, access: "read" | "edit", source: "exact" | "inferred" }[]` 字段，`target` 的截断不变。适配器改动后 D5 的 token 对账必须仍然 100% 一致。
2. **时间（我的决定）**：
   - 默认视图是「现在」，也就是时间轴末端。拖动时间轴回看历史。
   - 街区布局**只算一次**：每个地块、路段、房子记录首次出现时间，按当前时刻过滤显示，不在每个时刻重算。
   - 昼夜取当前时刻在本机时区的钟点。
   - 天气用摘要里的数据：按任务成败，加上每个任务的失败调用数。摘要因此加一个 `failedCalls` 字段。
3. **房子与地块共用街道（我的决定）**：
   - 地块贴街；房子在地块后面一排。
   - 房子在**落成那一刻**就定下所在街道：按它自己改动最多的一级目录，之后不再移动。
   - 槽位按任务完成顺序分配。超出上限时最老的不画，其余房子位置不变。
   - 没改文件的任务、根目录文件：在广场外圈分两个半环，满了向外加一圈。
   - 房子也做「加一个新任务，已有房子不动」的稳定性测试。
4. **项目根（我的决定）**：
   - 从会话的 cwd 往上找 `.git`，找到就用仓库根，找不到就用 cwd。这样同一仓库不同子目录的会话合成一个镇。
   - worktree 按它自己的根算，单独成镇。
   - 测试另做**带合成路径的 fixtures**：路径是编造的，不来自真实日志。演示数据也补上真实形态的相对路径。
5. **任务标题（我的决定）**：
   - 每个任务用它第一条用户消息的首行，截到 80 字。`ai-title` 只作会话名，显示在日记的抬头。
   - 标题可以出现在 `/api/world` 里（只在本机）。
   - `event.ts` 里 title 的注释改为「本机显示用」。
6. **Codex 的生活细节（我的决定）**：
   - Codex 日志里没有「等你」事件，就不摇铃，不编。
   - 拒绝事件用 guardian 审批的结论：日志里有拒绝结论才落栏杆。
   - 小人服装用它**最近一次模型调用**的模型。
7. **「进行中」（我的决定）**：
   - 判定：没见到 `task_end`，且源文件 10 分钟内有写入。
   - 同时最多 6 个工地完整动画，取最近活动的 6 个。其余在镇的横幅上显示「施工中」，不展开。
